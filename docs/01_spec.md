## 1. 学習の対象

`guides/03_cypher_reference_ja.html` の **30 枚のカード**をそのまま学習単位とする。

各カードは「**構文**」と「**その構文が何のためのものか（一行の役割）**」の対を持っている。これがそのまま出題の表と裏になる。

章は guide の見出しをそのまま使う。`id` は表示名ではなく安定した slug（理由は後述）。

| id | 章（guide の見出し） | カード | 枚数 |
|---|---|---|---:|
| `skeleton` | 読み取りの骨格 | `MATCH` `OPTIONAL MATCH` `WHERE` `WITH` `RETURN` | 5 |
| `patterns` | パターンの書き方 | `( )` `-[ ]->` `*1..3` `p = (…)` `shortestPath` `EXISTS { }` | 6 |
| `shaping` | 結果の整形 | `ORDER BY` `SKIP / LIMIT` `DISTINCT` `UNION` | 4 |
| `lists` | リストと集約 | `count/sum/avg…` `collect( )` `UNWIND` `パターン内包表記` `リスト関数・述語` `CASE / coalesce` | 6 |
| `writing` | 書き込み | `CREATE` `MERGE` `SET / REMOVE` `DELETE` `FOREACH` | 5 |
| `subqueries` | サブクエリ・スキーマ・診断 | `CALL { }` `CALL … YIELD` `CONSTRAINT / INDEX` `EXPLAIN / PROFILE` | 4 |
| | | | **30** |

**章は飾りではない。** 「誤答肢を同じ章から引く」（[§2](#2-出題形式)）ために使う、機能上必要なデータ。日本語の章名を id にすると文言を直した瞬間にキーが壊れるので、slug を id とし日本語は表示ラベルとして別に持つ（[`02_architecture.md`](./02_architecture.md#4-デッキ生成)）。

全 30 枚の内容は [`05_reference.md`](./05_reference.md#30-枚のカード) に一覧がある。

## 2. 出題形式

4 択のフラッシュカード。**両方向**出す。

### 正順 — 構文 → 目的

```
┌─────────────────────────────────────────────┐
│  OPTIONAL MATCH                             │
│                                             │
│  1. グラフの中から、指定した形に当てはまる     │
│     組み合わせをすべて探して行にする          │
│  2. 見つからなくても行を捨てず、             │  ← 正解
│     変数を null にして通す                   │
│  3. 直前の MATCH または WITH の結果を絞る     │
│  4. クエリを前半と後半に区切り、             │
│     結果を渡す関所                           │
└─────────────────────────────────────────────┘
```

### 逆順 — 目的 → 構文

```
┌─────────────────────────────────────────────┐
│  見つからなくても行を捨てず、                 │
│  変数を null にして通す                      │
│                                             │
│  1. MATCH                                   │
│  2. OPTIONAL MATCH                          │  ← 正解
│  3. WHERE                                   │
│  4. WITH                                    │
└─────────────────────────────────────────────┘
```

### 正順と逆順は別々に習熟度を数える

「`OPTIONAL MATCH` の意味は言えるが、"該当なしを残したい" という状況から `OPTIONAL MATCH` が出てこない」——この状態は普通に起きる。**認識できることと、思い出せることは別**なので、別々にカウントする。

### 誤答肢は同じ章から優先的に取る

`OPTIONAL MATCH` の誤答肢が `MATCH` `WHERE` `WITH`（同じ `skeleton`「読み取りの骨格」の章）になるほうが、`CREATE` が混ざるより遥かに紛らわしく、学習になる。

同じ章で足りなければ全体から補充する。

## 3. カードの裏

回答するとカードが裏返り、以下が出る。

| 要素 | 内容 |
|---|---|
| **正誤** | 選んだ肢 / 正しい肢 |
| **サンプルクエリ** | guides と同じ手書きシンタックスハイライト |
| **期待される実行結果** | guides の実測値。**DB に繋がなくても見える** |
| **補足の解説** | guides の本文 |
| **罠** | 該当するカードのみ。例:「`count(t)` と `count(DISTINCT t)` の取り違えで 13 が 20 になる」 |

---

## 4. クエリの実行と編集

**カード裏のサンプルクエリは、編集して実行できる。**

これは guides が繰り返し推奨している学び方をそのまま操作にしたもの。guides の言葉を借りれば——

> 罠はまず**間違った版を流して見せる**のが一番効きます。

1 文字〜1 語の変更で答えが変わる例が、教材側にすでに揃っている。

| カード | 編集 | 何が起きるか |
|---|---|---|
| `optional-match` | `OPTIONAL MATCH` → `MATCH` | Killua Zoldyck が消えて 29 人になる |
| `distinct` / `with` | `count(DISTINCT t)` → `count(t)` | 答えが **13 から 20 に飛ぶ** |
| `varlen` | `*1..3` → `*1..1` | 7 件が 4 件になる |
| `edge` | `-[:DEPENDS_ON]->` → `<-[:DEPENDS_ON]-` | upstream が blast radius に反転する |
| `shortest` | `-[:DEPENDS_ON*]-` → `-[:DEPENDS_ON*]->` | **0 件になる** |

### 実行は読み取り専用

書き込みクエリは実行前に拒否する。

これは**セキュリティ境界というより教材の安全装置**（受講者が共有 DB を壊さない）。UI の文言もその位置づけで書く。

### 書き込み系 5 枚は実行ボタンを出さない

`CREATE` `MERGE` `SET` `DELETE` `FOREACH` の 5 枚。代わりに guides に載っている**実行前後の状態**を静的に見せる。

```
実行前   (billing-engine:Service)
実行後   (billing-engine:Service:Upstream)
```

### 実行可能性の内訳（実測）

| 区分 | 枚数 | 備考 |
|---|---:|---|
| 単体で実行でき、期待結果も揃っている | **22** | |
| 書き込み系 | **5** | `CREATE` `MERGE` `SET` `DELETE` `FOREACH` |
| 構文列挙のみで単体実行に向かない | **5** | `RETURN` `( )` `DISTINCT` `CASE` `CONSTRAINT/INDEX` |

## 5. DB への接続

> **接続情報はクイズ開始時にユーザーが入力する。アプリ側で保持も保存もしない。**

- **入力するもの** — URI / ユーザー名 / パスワード /（任意で）データベース名
- **接続先は選ばない** — ローカルの Docker（`bolt://localhost:7687`）でも、各自の Neo4j Aura（`neo4j+s://...`）でもよい
- 接続に成功すると、以降のクエリ実行では**パスワードを二度と送らない**
- **タブを閉じると接続は切れ、再入力になる**
  手間だが「パスワードを管理しない」を実効的に守るための**意図的な仕様**
- **接続しなくてもクイズは通しで解ける。** 実行機能だけが無効になる
  （裏面の期待結果は静的に出るので、学習そのものは成立する）

### 開発時だけの例外 — 自動接続

**上記は受講者が使う本番の挙動。** 開発中に毎回パスワードを打つのは無駄なので、**dev 限定で自動接続する**。

- 開発者が `.env` に**ローカル Docker の使い捨て資格情報**を書いておくと、アプリ起動時に自動で繋がった状態から始まる
- 自動接続が効いている間は、画面にそれが分かる表示を出す
- **手入力の経路もいつでも試せる** — 切断ボタンで通常の接続画面に戻れる（本番の挙動を開発中に確認するため）

この経路では**パスワードがブラウザに一切渡らない**（サーバが自分の設定を読んで繋ぐだけ）ので、本番の手入力経路より露出が少ない。

**受講者に配る形では無効。** 有効化には明示的な設定が必要で、本番設定では起動を拒否する。詳細は [`03_api.md`](./03_api.md#4-開発時の自動接続dev-限定)。

## 6. 復習（間隔反復）

Leitner 方式の簡略版。SM-2 のような複雑なスケジューリングは要らない。

```
                  正答
   box 0  ──────────────▶  box 1  ──────────────▶  box 2 （完了）
     ▲                       │                       │
     └───────────────────────┴───────────────────────┘
                  誤答（キューの数枚後ろに差し戻す）
```

- **カード × 方向**（正順 / 逆順）ごとに `box: 0 | 1 | 2` を持つ
- **正答** → `box + 1`
- **誤答** → `box = 0` に戻し、**キューの数枚後ろに差し戻す**（そのセッション中にもう一度出る）
- **完了条件** — 全ての カード×方向 が `box >= 2` ＝ 2 回連続で正答
- 進捗は端末に保存され、次回は `box` の低いものから出る
- 「同じ順番でもう一度」ができるよう、**出題順と肢の並びは再現可能**にする

## 7. 画面と導線

```
 [接続画面]  ──任意でスキップ──▶  [出題]  ⇄  [カード裏]  ──▶  [サマリ]

 URI                              4 択      正誤・解説        正答率
 ユーザー名                                 サンプルクエリ     誤答カード一覧
 パスワード                                 編集して実行       もう一度
 ─────────                                 実行結果          誤答だけもう一度
 接続 / スキップ
```

- **進捗バー**（残り枚数と box の分布）を常時表示
- **light / dark テーマの切替**を付ける
  guides は両方のパレットを持っているが JS がないため切替 UI がない。**このアプリで初めて付けられる**

## 8. 意匠

guides の意匠をそのまま引き継ぐ。CSS 変数の意味づけが徹底されているので、クイズの状態に素直に写せる。

| 変数 | guides での意味 | クイズでの用途 |
|---|---|---|
| `--accent` | 構造・リンク・キーワード | 選択中の肢、進捗バー |
| `--trace` | **答え・根拠パス** | 正解の表示、カード裏 |
| `--alarm` | 誤り・危険 | 誤答、罠ブロック |
| `--keep` | フィルタを通過して残る行 | 正答 |
| `--team` `--engineer` `--service` `--incident` | エンティティ 4 色 | 結果表のノード種別チップ |

具体的な色値・フォントは [`05_reference.md`](./05_reference.md#意匠) を参照。

- シンタックスハイライトは**ライブラリを使わない**。guides と同じ手書きクラス体系を維持する
- UI 言語は**日本語のみ**（guides が全て `_ja` のため）
