技術は [`02_architecture.md`](./02_architecture.md) と [`03_api.md`](./03_api.md)。

## 1. 学習の対象

`guides/03_cypher_reference_ja.html` の **30 枚のカード**をそのまま学習単位とする。

各カードは「**構文**」と「**その構文が何のためのものか（一行の役割）**」の対を持っている。これがそのまま出題の表と裏になる。

章は guide の見出しをそのまま使う。`id` は表示名ではなく安定した slug（理由は後述）。

| id | 章（guide の見出し） | カード | 枚数 |
|---|---|---|---:|
| `skeleton` | 読み取りの骨格 | `MATCH` `OPTIONAL MATCH` `WHERE` `WITH` `RETURN` | 5 |
| `patterns` | パターンの書き方 | `( )` `-[ ]->` `*1..3` `p = (…)` `shortestPath` `EXISTS { }` | 6 |
| `shaping` | 結果の整形 | `ORDER BY` `SKIP / LIMIT` `DISTINCT` `UNION` | 4 |
| `lists` | リストと集約 | `count/sum/avg…` `collect( )` `UNWIND` `パターン内包表記` `リスト関数・述語` `CASE / coalesce` | 6 |
| `writing` | 書き込み | `CREATE` `MERGE` `SET / REMOVE` `DELETE` `FOREACH` | 5 |
| `subqueries` | サブクエリ・スキーマ・診断 | `CALL { }` `CALL … YIELD` `CONSTRAINT / INDEX` `EXPLAIN / PROFILE` | 4 |
| | | | **30** |

**章は飾りではない。** 「不正解の肢を同じ章から引く」（[§2](#2-出題形式)）ために使う、機能上必要なデータ。日本語の章名を id にすると文言を直した瞬間にキーが壊れるので、slug を id とし日本語は表示ラベルとして別に持つ（[`02_architecture.md`](./02_architecture.md#4-デッキ)）。

全 30 枚の内容は [`05_reference.md`](./05_reference.md#30-枚のカード) に一覧がある。

## 2. 出題形式

4 択のフラッシュカード。**両方向**出す。

### 正順 — 構文 → 目的

```
┌─────────────────────────────────────────────┐
│  OPTIONAL MATCH                             │
│                                             │
│  1. グラフの中から、指定した形に当てはまる     │
│     組み合わせをすべて探して行にする          │
│  2. 見つからなくても行を捨てず、             │  ← 正解
│     変数を null にして通す                   │
│  3. 直前の MATCH または WITH の結果を絞る     │
│  4. クエリを前半と後半に区切り、             │
│     結果を渡す関所                           │
└─────────────────────────────────────────────┘
```

### 逆順 — 目的 → 構文

```
┌─────────────────────────────────────────────┐
│  見つからなくても行を捨てず、                 │
│  変数を null にして通す                      │
│                                             │
│  1. MATCH                                   │
│  2. OPTIONAL MATCH                          │  ← 正解
│  3. WHERE                                   │
│  4. WITH                                    │
└─────────────────────────────────────────────┘
```

肢を選んだ時点では回答にしない。**決定**を押して確定する。押し間違いをそこで取り消せる。

### 正順と逆順は別々に習熟度を数える

「`OPTIONAL MATCH` の意味は言えるが、"該当なしを残したい" という状況から `OPTIONAL MATCH` が出てこない」——この状態は普通に起きる。**認識できることと、思い出せることは別**なので、別々にカウントする。

### 不正解の肢は同じ章から優先的に取る

`OPTIONAL MATCH` の不正解の肢が `MATCH` `WHERE` `WITH`（同じ `skeleton`「読み取りの骨格」の章）になるほうが、`CREATE` が混ざるより遥かに紛らわしく、学習になる。

同じ章で足りなければ全体から補充する。

## 3. カードの裏

回答するとカードが裏返り、以下が出る。

| 要素 | 内容 |
|---|---|
| **正誤** | 選んだ肢 / 正しい肢 |
| **サンプルクエリ** | 手書きのシンタックスハイライト |
| **期待される実行結果** | 確認済みの実測値。**DB に繋がなくても見える**。guides の整形済みテキストをそのまま出す |
| **実行結果** | 実行したときだけ出る。ドライバが返す行と列なので**表で出す**。期待値の下に積む |

**ノードとして返った値だけ、ラベルの色を字に付ける**（`RETURN up` のような形）。
`s.name` のようにプロパティで返った値は、種別が分からないので色を付けない。
| **補足の解説** | カードごとの解説文 |
| **罠** | 該当するカードのみ。例:「`count(t)` と `count(DISTINCT t)` の取り違えで 13 が 20 になる」 |

**表と裏は同時に出ない。** 同じ画面に並ぶと、答えを見ながら肢を選べてしまう。

**裏から次へ進むのは押して決める。** 自動では送らない——クエリを編集して実行できるので、
読み終わる時間は人によって違う。最後の 1 枚では進む先が結果になる。

**不正解のときは選んだ肢と正しい肢が並ぶ。** どちらにも見出しを付ける——正しい肢の側だけ
見出しが無いと、2 つのどちらが答えなのかが読めない。

## 4. クエリの実行と編集

**カード裏のサンプルクエリは、編集して実行できる。**

編集ボタンを押すまでは色付きのまま出し、押すと本文が編集欄に入る。
**注釈（`←` や言い換え）は本文に入れない**——そのまま送ると構文エラーになる。

**編集欄を出さないのは書き込みのカードだけ。** 構文を列挙したカード（`-[:R]->` の一覧など）は
そのままでは 1 本のクエリにならないが、**書き換えて試せる**ほうが学べる。
押せば構文エラーが編集欄の下に出る——それも「間違った版を流して見せる」の一部。

これは guides が繰り返し推奨している学び方をそのまま操作にしたもの。guides の言葉を借りれば——

> 罠はまず**間違った版を流して見せる**のが一番効きます。

1 文字〜1 語の変更で答えが変わる例が、教材側にすでに揃っている。

| カード | 編集 | 何が起きるか |
|---|---|---|
| `optional-match` | `OPTIONAL MATCH` → `MATCH` | Killua Zoldyck が消えて 29 人になる |
| `distinct` / `with` | `count(DISTINCT t)` → `count(t)` | 答えが **13 から 20 に飛ぶ** |
| `varlen` | `*1..3` → `*1..1` | 7 件が 4 件になる |
| `edge` | `-[:DEPENDS_ON]->` → `<-[:DEPENDS_ON]-` | upstream が blast radius に反転する |
| `shortest` | `-[:DEPENDS_ON*]-` → `-[:DEPENDS_ON*]->` | **0 件になる** |

### 実行は読み取り専用

書き込みクエリは実行前に拒否する。

これは**セキュリティ境界というより教材の安全装置**（受講者が共有 DB を壊さない）。UI の文言もその位置づけで書く。

### 書き込み系 5 枚は実行ボタンを出さない

`CREATE` `MERGE` `SET` `DELETE` `FOREACH` の 5 枚。代わりに guides に載っている**実行前後の状態**を静的に見せる。

```
実行前   (billing-engine:Service)
実行後   (billing-engine:Service:Upstream)
```

### 実行可能性の内訳（実測）

| 区分 | 枚数 | 備考 |
|---|---:|---|
| 単体で実行でき、期待結果も揃っている | **20** | |
| 書き込み系 | **5** | `CREATE` `MERGE` `SET` `DELETE` `FOREACH` |
| 構文列挙のみで単体実行に向かない | **5** | `RETURN` `( )` `DISTINCT` `CASE` `CONSTRAINT/INDEX` |

## 5. DB への接続

> **接続情報はクイズ開始時にユーザーが入力する。アプリ側で保持も保存もしない。**

- **入力するもの** — URI / ユーザー名 / パスワード /（任意で）データベース名
- **接続先は選ばない** — ローカルの Docker（`bolt://localhost:7687`）でも、各自の Neo4j Aura（`neo4j+s://...`）でもよい
- 接続に成功すると、以降のクエリ実行では**パスワードを二度と送らない**
- **タブを閉じると接続は切れ、再入力になる**
  手間だが「パスワードを管理しない」を実効的に守るための**意図的な仕様**
- **接続しなくてもクイズは通しで解ける。** 実行機能だけが無効になる
  （裏面の期待結果は静的に出るので、学習そのものは成立する）
- **画面は「接続は任意」の案内 → 入力欄 → 保存しない旨、の順**に置く。パスワードを求める
  欄を先に見せると、入れないと始められないように読める
- **保存しないことと、タブを閉じると切れることを画面に書く。** 入力の手間が仕様だと分かる

### 開発時だけの例外 — 自動接続

**上記は受講者が使う本番の挙動。** 開発中に毎回パスワードを打つのは無駄なので、**dev 限定で自動接続する**。

- 開発者が `.env` に**ローカル Docker の使い捨て資格情報**を書いておくと、アプリ起動時に自動で繋がった状態から始まる
- 自動接続が効いている間は、画面にそれが分かる表示を出す
- **手入力の経路もいつでも試せる** — 切断ボタンで通常の接続画面に戻れる（本番の挙動を開発中に確認するため）

この経路では**パスワードがブラウザに一切渡らない**（サーバが自分の設定を読んで繋ぐだけ）ので、本番の手入力経路より露出が少ない。

**受講者に配る形では無効。** 有効化には明示的な設定が必要で、本番設定では起動を拒否する。詳細は [`03_api.md`](./03_api.md#4-開発時の自動接続dev-限定)。

## 6. 復習（間隔反復）

Leitner 方式の簡略版。SM-2 のような複雑なスケジューリングは要らない。

```
                  正解
   box 0  ──────────────▶  box 1  ──────────────▶  box 2 （完了）
     ▲                       │                       │
     └───────────────────────┴───────────────────────┘
                  不正解（キューの数枚後ろに差し戻す）
```

- **カード × 方向**（正順 / 逆順）ごとに `box: 0 | 1 | 2` を持つ
- **正解** → `box + 1`
- **不正解** → `box = 0` に戻し、**キューの数枚後ろに差し戻す**（そのセッション中にもう一度出る）
- **完了条件** — **選んだ章の**全ての カード×方向 が `box >= 2` ＝ 2 回連続で正解
  （章の選択は [§7](#スタート画面--出す章を選ぶ)）
- 進捗（box）と成績は端末に保存され、次回は `box` の低いものから出る
- **出題順と肢の並びは毎回ランダム。** 同じ並びで繰り返すと、内容ではなく順番を覚える
  シードはセッションの初めに引く。**同じシードなら同じ並び**になるので、テストでは固定できる

## 7. 画面と導線

```
 [接続画面]  ──任意でスキップ──▶  [出題]  ⇄  [カード裏]  ──▶  [サマリ]  ⇄  [復習]

 URI                              4 択      正誤・解説        正解率            設問
 ユーザー名                                 サンプルクエリ     不正解カード一覧    正誤・解説
 パスワード                                 編集して実行       もう一度          編集して実行
 ─────────                                 実行結果          不正解だけもう一度  結果へ戻る
 接続 / スキップ
```

### スタート画面 — 出す章を選ぶ

**6 つの章をチェックで選ぶ。初めて開いたときは何も選ばれていない。**
1 つも選んでいなければ始められない——**何を出すかは必ず本人が決める。**

**一覧の先頭に「全て」の行を置く。** チェックすると 6 章すべてが入り、外すと全部外れる。
章を 1 つでも外すと「全て」も外れる。

**チェックした章は端末に残す。** 次にアプリを開いたとき、前回チェックしていた章が
チェックされたまま出る——毎回選び直さずに済む。進捗（box）とは別に持つ。

```
 出す章
  [ ] 全て                 60 問・最初から
  ─────────────────────────────────────────
  [ ] 読み取りの骨格             0 / 10
  [ ] パターンの書き方           8 / 12
  [ ] リストと集約                進行中     ← 章ごとの状態は各行の右端
```

**「全て」の行の右端には `60 問・最初から` と出す**——各章の状態と無関係に 60 問出ることを、
選ぶ前に見せる。

**「全て」は総ざらい。** 6 章すべてが選ばれているときは、**各章の状態に関わらず全 60 問を
最初から出す**（下の表より優先する）。始めるときに全章の box と成績を消す。
解いた結果は、そのまま各章の状態になる。

**サマリの「もう一度」はこの画面へ戻る。** 章を選び直してから解き直せる。
「不正解だけもう一度」は章を変えないので、出題へ直に戻る。

#### 章の行 — 何問正解しているかと、次に何が出るか

**行には `正解した問題 / その章の問題数` を出す。** 未着手でも `0 / 10` と出し、表記を分けない。
**分子は問題の数**で、回答の回数ではない（同じ問題に 3 回答えても 1 問）。

**その章の問題を全て正解していれば、`10 / 10` を強調して出す。**
1 問でも間違えていれば、完了していても他の行と同じ出方にする。

**解きかけの章だけは数を出さず `進行中` と出す。** 途中の数は成績ではない——
まだ出ていない問題があるので、`2 / 10` を他の章の `8 / 10` と並べると比べられてしまう。

| 章の状態 | 行 | 選ぶと出る | 始めるときに消すもの |
|---|---|---|---|
| 未着手 | `0 / 10` | 全問 | なし |
| 解きかけ | `進行中` | 完了していない問題（続き） | なし |
| 完了 | `8 / 10` | **全問**（最初から） | その章の box と成績 |

**完了した章を選ぶと、間違いの有無に関わらず全問を最初から出す。**
間違えた問題だけを解き直すのは**サマリの「不正解だけもう一度」の役目**で、スタート画面には置かない
——スタート画面は「どの章をやるか」だけを決める場所にする。

**解きかけは、クイズ画面を閉じて開き直したときだけ起きる。** 出題を始めたら、
完了するまでスタート画面へ戻る導線が無い。**回答があり、まだ完了していない章**がこれに当たる。

**上の表を適用するのは、6 章のうち一部を選んだときだけ。** 全て選んだときは総ざらいになる。

#### 章ごとの記録リセット

**行に記録を消すボタンを置く。** その章の box と成績を消し、未着手に戻す。
**解きかけの章を最初からやり直したいとき**に使う——解きかけを選ぶと続きから出るため。

回答が 1 つも無い章には出さない。**確認は出さない**——消えるのはその章だけで、解き直せば戻る。

#### ボタン

| | |
|---|---|
| **文言** | `開始`。**状態で変えない**——何問出るかは章の行が持っている |
| **何も選んでいないとき** | 無効 |

#### 選んだ章に限るもの

**保存の形は変えない。** 章はキー（`カードID:向き`）から引けるので、box も成績も
今のまま 1 つに持つ。**数える範囲を選んだ章に限る**ことで、章ごとの進捗になる。

| | |
|---|---|
| 完了条件 | 選んだ章の**出た問題**が全て box 2 |
| 進捗バー | 分母は選んだ章の分だけ |
| 章別の成績 | 選んだ章だけ並べる。**選ばなかった章の成績は変更されない** |
| 不正解だけもう一度 | 選んだ章の間違えた問題だけ |

**途中で再開しても、選んだ章だけが出る。** 前回どの章で終えたかは出題に影響しない。

**「間違えた問題だけ解く」の結果は、スタート画面の成績には反映されない。**

サマリに出すもの。

| 要素 | 内容 |
|---|---|
| **正解率** | 全体の割合と、出題数に対する正解数 |
| **章別の成績** | 章ごとに正解 / 出題。**全問正解の章は色で分かる** |
| **不正解カード一覧** | カード名と方向（`構文 → 目的` / `目的 → 構文`）。**行を押すとそのカードの裏を開く** |
| **やり直し** | 「もう一度」は**スタート画面へ戻る**（章を選び直す）。「不正解だけもう一度」は出題へ直に戻る。**全問正解なら後者は出さず**、「もう一度」が主になる |

### 復習の画面

不正解カード一覧の行を押して開く。**設問・正誤・解説・サンプルクエリの実行を 1 画面にまとめる。**

| 出すもの | 出さないもの |
|---|---|
| 設問（**カードの中**。「問題」と添える。書体は出題のときと同じ） | **進捗バー**——解き直しではないので、残り枚数は判断に使えない |
| 選んだ肢と正しい肢（当時のまま） | 4 択の肢——もう選ばない |
| 解説・罠・期待される実行結果 | |
| クエリの編集と実行 | |
| 「結果に戻る」ボタン | |

**答え直せない。** ここで解き直すと成績が変わり、何を間違えたかの記録でなくなる。
解き直すのは「不正解だけもう一度」の側。

**章別を出すのは、次に読み直す章が決まるため。** 全体の正解率だけでは、どこが弱いのかが分からない。
**選んだ章は、出題されなかったものも 0 / 0 で並べる**——抜けていると章どうしを比べられない。
**選ばなかった章は並べない**——今回の対象ではないものが 0 / 0 で並ぶと、解き残しに見える。

**成績が数えるのは問題であって、回答ではない。** 同じ問題に 3 回答えても出題数は 1
（進捗バーは逆に回答で数える。下）。
**1 度でも間違えた問題は、そのあと正解しても不正解**として数える。

**成績も box と一緒に端末に残す。** box は「2 回連続で正解したか」しか持たないので、
**出題数・正解数・間違えた問題は box から復元できない。**
残さないと、サマリでリロードしただけで正解率も不正解一覧も消える。
サマリに着いた時点では全て box 2 なので、「まだ完了していないもの」では不正解一覧にならない。

**「不正解だけもう一度」は間違えた問題だけを積み直す。** box はそのまま持ち越すので、
正解すればそのまま消え、また間違えれば 0 に戻ってもう一度出る。

- **進捗バー**は出題以降の画面で常時表示。スタートと接続では出さない
  - **数えるのは回答**で、問題の数ではない。
    **青 = 正解した回答 / 赤 = 間違えた回答 / 灰 = 完了までに残る回答**（各問 `2 - box` の合計）
  - **間違えると灰が増える。** 問題の数で数えると、60 問に 1 度ずつ答えた時点でバーが満杯になるが、
    完了には 120 回以上の回答が要る。満杯のまま出題が続く
  - **数字は出さない。** 間違えるたびに総数が増えるので、「残り N / M」は分母が動く
  - 復習の画面では出さない（[§7 の復習](#復習の画面)）
- **light / dark を切り替えられる。** 既定は light で、OS 設定にも追従する

## 8. 失敗の伝え方

**失敗は必ず画面に出す。** 保存できなかった、繋がらなかった、実行できなかった——どれも黙って続けない。

### 通知の帯

画面の**一番上**、進捗バーの上に積む。

| | |
|---|---|
| **何が出るか** | 何ができなかったか（見出し）と、サーバやブラウザからの文言（詳細。無いこともある） |
| **いつ消えるか** | 手で閉じるか、**同じことが次に成功したとき** |
| **同じ種類は 1 件** | 毎問走る保存が続けて失敗しても、帯は増えない |
| **画面を移っても残る** | 読む前に遷移で消えない |

**時間で自動的に消さない。** 読み終わる前に消えるのは、伝えていないのと同じ。

**本文に重ねない。** 帯が出た分だけ下の内容が下がる。隠れて読めない部分を作らない。

### 続けられる失敗と、続けられない失敗

| | 例 | 出し方 |
|---|---|---|
| 続けられる | 進捗を保存できない | 金の帯。**解き進められる**ことを文言に書く |
| 続けられない | DB に繋がらない、DB が応答しない | 赤の帯 |

### 送ったクエリが原因の失敗は、カードの中に出す

**帯に出すのは、繋ぎ直しや読み込み直しが要るものだけ。** クエリを書き直せば済む失敗は、
書いた場所のすぐ下に出す——帯に上げると、どのクエリの話かが読めなくなる。

| 失敗 | どこに |
|---|---|
| 構文が違う / 送った内容が不正 / 時間を超えた | **カードの中**（編集欄の下） |
| 書き込みのクエリを拒否した | **カードの中**。決まった文言で、歯止めであることを書く |
| DB に繋がっていない / 繋がらない / 想定外 | **赤の帯** |

**時間を超えたものをカードに入れるのは、教材のクエリが一瞬で返るため。**
超えるのは止め方を間違えた可変長パスなど、書き方が原因のもの。

進捗を保存できない端末でも、クイズそのものは最後まで解ける。**次回が最初からになる**だけ。
そのため保存された進捗が壊れていたときは、何も出さずに最初から始める——利用者に判断することが無い。

### 画面そのものを出せないとき

白い画面にしない。**何が起きたかと「読み込み直す」を出す。**

## 9. 意匠

**編集物／印刷レポートの佇まい。** アプリ UI らしさを出さない。

| 何を | どう見せるか |
|---|---|
| 選択中の肢 | 青の罫線と淡い面 |
| 正解 | 緑 |
| 不正解 | 赤 |
| 注意・罠 | 金 |
| 結果表のノード種別 | Team / Engineer / Service / Incident に 4 色 |

**「正解」を表す色は緑だけ。** 金は注意・罠の専任。

- シンタックスハイライトは**ライブラリを使わない**。色分けは出題データが持つ
- UI 言語は**日本語のみ**

色値・書体・文字の段階は [`07_design.md`](./07_design.md) が正。
