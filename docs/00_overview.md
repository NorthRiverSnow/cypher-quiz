# cypher-quiz — 全体像

NordWind ワークショップの Cypher 教材を、読むだけの資料から**定着を確認できる練習**に変えるアプリ。

---

## なぜ作るのか

`../nordwind-workshop/guides/` に Session 3（Neo4j / Cypher）の解説教材が 3 本ある。

| ファイル | 主題 |
|---|---|
| `01_depends_on_traversal_ja.html` | 可変長パス `*1..3` が「テーブル走査ではなくポインタ追跡」である仕組み |
| `02_match_and_with_ja.html` | `MATCH` のカンマと `WITH`。行数が 52 → 20 → 13 → 1 と畳まれる過程 |
| `03_cypher_reference_ja.html` | Cypher 構文の早見表。**30 枚のクローズカード** |

どれも読み物として完成しているが、**定着を確認する手段がない**。

> 受講者が「MATCH は読んだ」で終わらず、
> **「OPTIONAL MATCH を使うのはどういうときか」を即答できる**状態にする。

これが本アプリの目的。

## 何を作るのか（一行で）

> `03_cypher_reference_ja.html` の 30 枚のカードを **4 択のフラッシュカード**にし、
> カード裏のサンプルクエリを**実際の Neo4j で実行・編集**できるようにしたもの。

出題は「クエリを書かせる」のではなく「**構文に対して、それが何のためのものかを選ばせる**」。

## 現状

`cypher-quiz` リポジトリは**空**（`.git` のみ、コミットゼロ）。全て新規。

## 決定事項の一覧

### 仕様

| 項目 | 決定 |
|---|---|
| 学習単位 | `guides/03` の 30 枚のカード |
| 出題形式 | 4 択。**正順（構文 → 目的）と逆順（目的 → 構文）の両方** |
| 誤答肢 | **同じセクションから優先的に取る**（紛らわしいほうが学習になる） |
| 復習 | Leitner 方式の簡略版。誤答は同一セッション内で再出題 |
| 完了条件 | 全ての カード×方向 を 2 回連続で正答 |
| クエリ実行 | **サンプルを編集して再実行できる**。ただし読み取り専用 |
| 書き込み系 5 枚 | 実行させない。guides の実行前後の状態を静的に見せる |
| DB 接続 | **開始時にユーザーが入力。アプリは保持も保存もしない** |
| 開発時のみ | `.env` の資格情報で**自動接続**。切断すれば手入力の経路も試せる |
| 未接続時 | クイズは通しで解ける。実行機能だけ無効 |
| 進捗保存 | 端末に保存。ただし**接続情報は保存しない** |
| UI 言語 | 日本語のみ |
| 意匠 | guides の CSS 変数体系をそのまま引き継ぐ。light / dark 切替あり |

### 技術

| 項目 | 決定 |
|---|---|
| 言語 | TypeScript（全層） |
| 設計様式 | **関数型。クラスを使わない** |
| 層の分離 | **MVC**（Model / View / Controller）を関数型で実現 |
| フロント | Vite + React |
| コンポーネント開発 | **Storybook。ここから着手する** |
| バックエンド | **Hono** + `@hono/zod-openapi` |
| スキーマ | Zod。**型・実行時検証・OpenAPI の唯一の真実** |
| セッション | **httpOnly クッキー。フロントは識別子を持たない** |
| DB ドライバ | `neo4j-driver` v5 |
| dev 環境 | Docker Compose |
| 構成 | npm workspaces のモノレポ |
| 境界の担保 | ESLint（規約ではなく機械で落とす） |

## 進め方

**フェーズ A（Storybook で画面の雰囲気を決める）で一度止めて確認をもらう。**
DB も API もモデルも無しに、固定データだけで画面を組む。そこが固まってから中身に進む。

詳細は [`04_roadmap.md`](./04_roadmap.md)。

```
A. Storybook で見た目          ← ここから。確認をもらって止まる
B. モデル（純関数）
C. バックエンド（Docker + Hono）
D. 結線
```
