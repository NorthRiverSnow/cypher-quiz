# フックを作る

## 1. 入れる前に試す

**`settings.json` に書く前に、標準入力を模して直接流す。**

```
echo '{"hook_event_name":"Stop","cwd":"'"$PWD"'"}' | python3 .claude/hooks/x.py; echo "exit=$?"
```

**通る場合と黙る場合の両方を試す。** 黙るはずの入力で出力が出ないことまで確認する
——「何も出ない」は成功と失敗の区別が付かない。

## 2. テキスト解析は Python

**BSD の `grep` は `\b`（単語境界）を解釈しない。** macOS でこれを使うと、
条件に当たらないまま素通りする。

## 3. 出力の形を選ぶ

| 出したい先                | 書く物                                                                                |
| ------------------------- | ------------------------------------------------------------------------------------- |
| 人の画面                  | `{"systemMessage": "…"}`                                                              |
| **Claude のコンテキスト** | `{"decision": "block", "reason": "…"}`（Stop を止めて続行させる）                     |
| SessionStart で文脈に足す | `{"hookSpecificOutput": {"hookEventName": "SessionStart", "additionalContext": "…"}}` |

**`systemMessage` は Claude に届かない。** 人が読んで伝え直すことになる。
Claude に直させたいなら `decision: "block"`。

## 4. 再帰を止める

`claude -p` の子セッションも**プロジェクトのフックを実行する**。何もしないと孫が動く。

- **`--settings '{"hooks":{}}'` では止まらない**（渡してもプロジェクトのフックは動く）
- 環境変数のガードが確実（子まで継承される）
- `stop_hook_active` と排他ロックは保険として重ねる

## 5. 握り潰さない

- **タイムアウトを「指摘なし」と同じ扱いにしない。** 終わらなかったことを出力する
- `claude -p` には `stdin=subprocess.DEVNULL` を渡す。渡さないと数秒待つ
- 走ったかどうかを後から確かめられるよう記録を残す。無言の失敗は「問題なし」に見える

## 6. パスは root からの相対

`vp test related` に絶対パスを渡すと `No test files found` で **1 件も実行されないまま exit 0** になる。

## 7. 誤検知を疑う

コマンド文字列を丸ごと調べるフックは、**heredoc の中の説明文にも反応する。**
禁止語を含む文章を書いただけで止まる。判定は実行される部分に絞る。
